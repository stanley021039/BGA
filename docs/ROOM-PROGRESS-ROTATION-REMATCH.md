## 提交狀態

玩家卡原有狀態只在 hover／focus tooltip 出現，平時只顯示完成框線。現在在卡片內保留固定高度的可讀狀態槽，桌機與窄版均可直接看到誰已完成、誰仍等待。只取伺服器已公開的 ID／布林值，離線文字與提交狀態並列；收回、換題及重連都從最新快照計算。

| 遊戲／階段 | 公開的完成依據 | 呈現 |
| --- | --- | --- |
| 一般同頻、殘酷二選一、猜歌／情境淘汰賽作答 | `participantIds`、`answeredIds` | 已選擇／已投票、等待中；晚入座另標下題／下局參與 |
| 送禮選擇 | `gaveIds`、`wishedIds` | 分別顯示送禮與心願；兩者都鎖定才完成 |
| 傳情畫意出題、傳頁 | 每席 `ready` | 已送出／等待中 |
| 極簡畫家作畫 | `readyIds` | 畫家已完成／等待；猜題者另標角色 |
| 瞎掰王看角色 | `readyIds` | 已準備／等待中 |
| 霧港跑團規劃 | 每席 `ready` | 已準備／等待中 |
| 猜歌前奏 | `readyIds` | 已選擇／等待中 |
| 猜歌插歌 | 已公開的 `challenges` 席位、`passed` | 已完成選擇／等待中；DJ 不列為等待插歌 |
| 郎中煮藥、結算 | `chosen`、停止／爆炸、該階段 `ready` | 常駐狀態；結算不沿用先前已停止作為本階段完成 |

撲克下注、雷霆行動及畫猜猜答案屬依序行動或可重複作答，沿用原有行動／猜中狀態，不增加不符合玩法的全員投票標記。揭曉前不讀取或顯示其他人的答案、送禮對象或投票對象。

## 輪替盤點（#258）

| 遊戲／模式 | 誰選擇／出題、順序 | 同時操作 |
| --- | --- | --- |
| 同頻一般 | 新局隨機首位；下一題依目前出題者的座位順序輪替。房主可在出題階段跳至下一位，不因此重抽。預備題按提交順序自動出題，第二題起由作者出題，後續輪替接續該作者；第一題保留隨機首位（既有規則） | 所有本題參與者含出題人一起秘密回答 |
| 殘酷二選一（組隊／個人／單人） | 系統牌庫同步出題，無玩家輪流選題；每人整局一次換題資格 | 同步選擇，組隊計分不代表兩人輪流提交 |
| 同頻猜歌／情境淘汰賽 | 系統抽取賽程與配對，全員投票；房主負責提前結算／前進 | 全員秘密投票 |
| 送禮 | 新局隨機發牌者，再依座位輪替；逐人確認收禮由本輪發牌者位置展開 | 送禮與心願秘密選擇 |
| 你畫我猜 | 新局隨機首位，按循環座位名單輪流當畫者；只有畫者選題 | 其他玩家可同時、重複猜答案 |
| 極簡畫家 | 隨機第一位猜題者，之後按座位輪替 | 其他玩家同時私人作畫 |
| 瞎掰王 | 隨機第一位想想，循環座位每人一次；想想選題 | 看角色共同準備；解釋／質問依原流程 |
| 猜歌挑戰 | 新局隨機 DJ，揭曉前進後依座位輪替 DJ | 前奏共同答題；插歌由其他玩家提交／放棄 |
| 霧港跑團 | 隨機第一幕領隊，逐幕循環座位；領隊選解法並檢定 | 隊員同時準備協助／整備 |
| 郎中闖江湖 | 隨機第一輪起始玩家，逐輪循環；占卜與市場依原角色／市場順序 | 煮藥與各必要效果保留原同步／準備規則 |
| 德州撲克 | 首手隨機莊位，後續手牌按有籌碼玩家輪替 | 下注依原行動順序 |
| 雷霆之路 | 骰子決定起始車隊，之後按原車隊回合順序 | 無全員投票 |

依據：各遊戲 `start`／`newRound`／`newScene`、同頻 `questionQueue` 與 `pass`、猜歌 `next`、雷霆起始擲骰。`tests/random-starter.test.js` 保留既有隨機首位及預備題例外測試；新增同頻跨完整循環、快照還原不重抽與四類模式的秘密／收回／換題測試。本票沒有發現需要把同步階段改成輪流的規則缺口，沒有改動輪替演算法。

## 重玩契約

十款有終局的遊戲（雷霆、同頻、送禮、畫猜、跑團、傳情、猜歌、極簡、瞎掰、郎中）統一呼叫 `POST /api/rematch`。只有房主且本局 `finished` 可返回；已在等待室的重複要求無副作用。即使人數低於開局門檻，也能先回等待室。

保留同一個房間物件、房號、有效座位／認證、房主／管理者、媒體與聊天，以及既有房間設定；清空上一局回合、答案、結果、倒數、暫存選擇與繪畫／傳頁緩衝。版本持續遞增，避免新等待狀態被客戶端視為舊快照；已完成歷史另存並保留。重新開局才依各遊戲原流程抽取首位與新局內容。撲克「再發一手」是連續牌局，不屬於終局重玩，保留籌碼與莊位輪替。

前端共用房間外殼攔截終局重玩；畫猜的專用外殼另接相同 API。設定區的 Teleport 依目標加 key，返回新建的等待室節點時重新掛載控制，避免舊結算節點卸載後遺失開始按鈕。等待室開局權限、人數、設定保存與郎中選書等原有流程持續生效。
