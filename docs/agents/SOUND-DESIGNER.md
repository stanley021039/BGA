# 音效師角色記憶

更新：2026-10-06。本輪為音效研究與設計提案；未下載、試聽、採購或整合新素材，未改程式。先讀 [記憶索引](README.md)、[共用決策](MEMORY-LEDGER.md)、[記憶協議](MEMORY-PROTOCOL.md)，再讀 [遊戲音效計畫](../specs/GAME-SOUND-PLAN.md)與 [素材來源研究](../research/SOUND-ASSET-SOURCES.md)。角色是可續讀的責任，不綁定目前 agent thread。

## 長期責任與設計理念

音效先回答「現在輪到誰、操作是否成功、公開事件發生了什麼」，再增加趣味。採短、柔和、可區辨的聲音；保持同一語意的一致音色，讓不同遊戲仍像同一個好友桌遊網站。背景音樂、影片、人聲與玩家角色表情會同時存在，聲音密度比素材數量重要。

每次提案由音效師列出已確認的 trigger、收聽對象、去重 key、呈現時間、音色／長度初值、靜音及失敗行為；程式方核對公開狀態與權限，玩家方驗可辨識性及疲勞。聲音不能替代文字、骰面、分數或合法操作提示；播放成功／結束不能推進遊戲規則。

素材按單一音檔／具體套件查授權，保留作者、原頁、授權版本與查核日、原檔及改作 hash、署名文字、用途與可否再散布。免費下載、免權利金、CC0與可放公開 repository 是不同問題；採用前重新查核，不把網站首頁當全部作品的授權。

## 評估準則

| 面向 | 可驗收問題 |
| --- | --- |
| 資訊價值 | 玩家聽到後是否知道發生什麼？關閉音效後，對應資訊仍完整可見。 |
| 公平與秘密資訊 | 音色、長短、音高、聲像與觸發時間是否只依收聽者已獲准取得的資訊？不以隱藏答案、秘密喜好或底牌強弱決定公共聲音。 |
| 節奏與同步 | 只播新的權威事件一次；不在 hydration、poll重繪、重連、回焦或手動回看重播。雷霆跟已確認位移及checkpoint呈現時序。 |
| 噪音與重複 | 八人同時猜題、連鎖受損及四段表情音效下，重要視覺仍可理解；高頻筆畫、hover、presence與每格移動不加聲。 |
| 偏好與清理 | 全部走AudioSettings.effects；音效與動畫偏好分開。mute／零音量／hidden／離頁立即停止，不排隊補播；拒播或載入失敗不阻擋操作。 |
| 聽感與素材品質 | 採用後檢查截音爆點、尖銳高頻、失真、頭尾靜音及音量落差；以小喇叭／耳機人工試聽。duration、waveform、解碼成功不是主觀聽感證據。 |
| 維護與授權 | 少量素材能覆蓋清楚語意；逐檔來源與license可追溯，公開原始碼及成品的分發權均可確認。 |

## 首批候選與實際討論

2026-10-06音效師與主agent（程式盤點／spec負責者）以訊息討論一次。主agent先提出畫猜本人猜中／輪到本人作畫、雷霆骰子與shot／slam／nitro／skid；音效師提出下表短音、私人提示與密度限制。主agent採納首批及合併方向，並修訂滿額政策。沒有玩家、美術或其他agent的回覆，不記為其他角色同意。

| 優先候選（設計推論） | 語意與收聽範圍 | 長度初值／理由 |
| --- | --- | --- |
| 畫猜本人猜中 | 本人已確認猜中時，一次柔和肯定聲；其他玩家仍看公開勾章。 | 150–300ms；回饋最明確，避免八人猜中變成全桌八聲。 |
| 畫猜輪到本人作畫 | 已確認新輪的drawer是本人，提示本人注意選題／作畫。 | 250–450ms；降低錯過自己回合的機會，不依題目內容變聲。 |
| 雷霆擲骰 | 已確認rolling開始，按check.id＋cycle一次；終骰揭示前聲音一致。 | 450–800ms；補目前沒有骰聲的互動，不能由預知結果音高洩漏點數。 |
| 雷霆公開動作 | shot／slam的短衝擊、nitro的短推進、skid的短摩擦；對齊onMove／onCue公開呈現。 | 200–700ms；各事件細分長度見spec，讓動作可區分，不在收到最終state時提前播結局。 |
| 雷霆一般移動（次於上四項） | 每個已確認指令最多一次短引擎；地形事件優先，不逐格播放或長loop。 | 300–600ms；多格移動有力度，同時控制重複。 |

密度初值為「非重要公開聲最小間隔250ms、遊戲事件同時最多2段」，沿用總共4段上限；同checkpoint的地震／多車受損合併一聲。這些是待實作及真人聽感驗證的假設，現在沒有兩段子上限。減動時直接同步state仍可對新的已確認事件播一次；聲音偏好不應被`MotionPolicy.allowsMotion`一併關閉。

音效師原提議讓關鍵輪次取代低優先音效；主agent修訂為首批不直接中斷玩家自訂表情音效，滿額允許捨棄新聲音並保留清楚視覺。關鍵提示被四段長表情占滿是已知缺口；若要保留聲道、優先級或淡出，須另由音效師／玩家驗證再設計。分類音量、ducking及新版混音器尚未實作。

秘密資訊邊界：送禮秘密喜好、同頻未揭曉答案與撲克底牌／手牌強弱，不得驅動公共音效。本人ACK可以短確認音；只有真正公開的揭曉／結算能使用公共結果聲。公開事件仍需依現有角色權限，不為音效新增能取得秘密資料的payload。

## 限制與下一步

這一輪只讀規範、程式與官方網頁；未自動播放音訊，未測喇叭、耳機、弱網、跨裝置或多人聽感。上述毫秒及密度不是無障礙標準，也不代表已實作、已上線或聽起來合適。

程式方先完成 [事件契約與去重規格](../specs/GAME-SOUND-PLAN.md)，再由音效師從可進repository的CC0具體包挑少量候選、逐檔重查license並建manifest。採用後做單次／重連／hidden／mute／滿額／載入失敗驗收；採用後安排人工試聽，依當次授權記錄收聽設備及音量，不把解碼成功當聽感證據。首批保持既有共用控制及秘密資訊邊界；不把角色表情音效10秒上限套成提示音目標。
