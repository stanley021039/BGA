# 你畫我猜：玩法與技術規劃

狀態：第一版已實作，本機驗證完成；Linux 與公開網域驗收追蹤於[實作進度](DRAW-GUESS-PROGRESS.md)。更新：2026-10-02。目標是 2–8 位受邀好友在手機或電腦上，輪流畫圖、即時猜題；沿用現有帳號、角色、房間與遊戲共用介面。第一版不用新增美術素材。

## 建議的第一版玩法

| 階段 | 玩家看到與操作的內容 | 伺服器規則 |
| --- | --- | --- |
| 等待 | 房間列表、角色、房主設定與開始按鈕 | 2–8 人可開始；每人輪流擔任一次畫者。 |
| 選題（15 秒） | 只有畫者看到三個詞；其他人看到「畫者正在選題」 | 逾時由伺服器從三題中選一題；題目與可接受別名留在伺服器，僅透過畫者的私人狀態送出。 |
| 畫圖與猜題（預設 90 秒） | 中央 512 × 256 畫布即時顯示筆畫；猜題者看到題材和字數、輸入猜測，畫者看到題目與工具列 | 畫者不能猜；每人每回合只計第一次答對。全部答對或倒數結束時揭曉。 |
| 揭曉（8 秒） | 公開正解、完成畫作、猜中次序和本輪得分 | 自動進入下一位畫者；房主可提前繼續。每人畫完一次後結算總分。 |

猜中者得分建議為 `30 + floor(70 × 剩餘秒數 ÷ 本輪秒數)`；畫者每有一名玩家猜中得 15 分。沒猜中不扣分，讓晚加入或畫得不熟的朋友也能繼續玩。先不加入近似答案的自動判分；只接受正解與題庫明列的別名，並在比對前做 Unicode NFKC、大小寫和空白正規化。這可避免「差一字」誤判，別名可處理「腳踏車／自行車」等常用說法。

首批題庫由專案自行編寫約 120 個可畫的日常詞，分為簡單／一般／挑戰三種難度。玩家可提交文字題目與別名到獨立的你畫我猜題庫；房主沿用現有的「依題庫比例、0、25、50、75、100%」投稿比例設定。題目只需文字，不依賴外部圖片授權。第一版避免抽象概念、品牌名和難以畫出的長句。

## 畫面與操作

- 主畫面沿用遊戲共用 UI：角色顯示、醒目的「輪到誰畫」、表情、離開按鈕。畫布占主要空間；手機版讓畫者有足夠手指操作區，猜題輸入固定在畫布下方。
- 畫者沿用畫室的色輪、常用色、筆刷大小、畫筆、橡皮擦、直線、矩形、圓形、復原與清空。將純畫布操作抽成共用模組；現有 `studio-editor.js` 與 `/studio` 頁面控制綁得很緊，不能直接整份放進遊戲頁。
- 對局中不開放匯入照片、帳號圖庫、去背或上傳檔案，避免預製圖片直接展示答案。揭曉後畫者可自行選擇把作品合成 PNG 存進私人帳號圖庫，沿用現有 1 MB 上限。
- 猜題輸入取代這款遊戲的文字彈幕輸入；錯誤猜測只短暫浮現在畫布旁，猜中的原文不向其他玩家廣播，只顯示「某某猜對了」。角色表情仍可用，避免另外出現一個常駐留言區。
- 題目文字只顯示給畫者；其他人只看題材與字數。進度以大字倒數、角色高亮及明顯的猜中標記呈現。減少動態設定下取消飛入動畫，畫圖本身仍保持即時。

## 目前架構要改的地方

| 範圍 | 建議改動 |
| --- | --- |
| 遊戲引擎 | 新增 `src/games/draw-guess.js`，只管理階段、選題、猜題、得分、時限、踢人與中途加入；所有判分與計時由伺服器決定。 |
| 畫布共用 | 從 `public/studio-editor.js` 抽出可共用的座標、色彩與筆畫／形狀渲染；畫室保留照片圖層和去背，遊戲頁只載入即時畫筆功能。 |
| 即時同步 | 新增房間專屬筆畫通道：畫者以小批次 HTTP POST 傳送座標與工具，伺服器以 SSE 推送給其他玩家。重連時先取得目前畫布的筆畫快照和版本，再追接增量事件；SSE 失敗時退回短輪詢。Cloudflare Tunnel 若要即時串流，來源回應必須設 `Content-Type: text/event-stream`，見 [Cloudflare Tunnel 疑難排解](https://developers.cloudflare.com/tunnel/troubleshooting/)。正式網域需實測延遲與重連。 |
| 房間與大廳 | 在 `src/app.js` 的建立／加入／路由加入明確的 `draw-guess` 類型，在 `src/rooms/listing.js` 設玩家數及中途加入規則，更新大廳遊戲卡與返回房間入口。未知類型目前會落到撲克，新增時應改為拒絕未支援的類型。 |
| 歷史 | `HistoryStore.transact` 會對每次操作寫入完整房間快照；筆畫不可逐段走這條路。筆畫只存在房間記憶體中的限量緩衝，回合結束時才將題目、畫者、答對者與分數等摘要寫進對局歷史。還要把新類型加入歷史完成判定與引擎來源對照。第一版不永久保存每一筆筆畫。 |
| 排程與重連 | `src/rooms/scheduler.js` 處理選題／作畫／揭曉期限；`src/rooms/reconnect.js` 恢復原座位與畫布。畫者離線超過 15 秒仍未回來則略過本輪；猜題者重連可繼續猜。 |
| 題庫 | 新增獨立題庫資料與必要的 SQLite 遷移；不能直接挪用同頻俱樂部的選項題格式。題目、別名、難度及投稿比例由伺服器抽取。 |

筆畫協定只接受工具白名單、`#RRGGBB` 色號、合法筆刷大小與 0–511／0–255 整數座標；建議每秒最多 10 批、每批最多 64 點，並對每輪總筆畫量與猜題長度設上限。每個事件帶房間、回合與遞增版本，舊回合或重複批次不重播。畫者身份由登入 session 與座位驗證，前端自報的玩家 ID 不可作為授權依據。畫布只使用 Canvas 繪製，不把玩家文字當 HTML／SVG 注入；題目、別名與猜測同樣需長度與字元檢查。這裡只做必要的安全及穩定性限制，不引入朋友投稿的審核流程。

## 中途加入與失線

遊戲開始後可加入房間並看當輪畫作，但從**下一輪**才正式猜題；這避免只看最後幾秒也拿到整輪分數。新玩家進入下一輪的猜題名單，當局畫者順序仍以開局時的人員為準；下一局再加入畫者輪替。被踢出的帳號不能重進同一房間。重新整理或暫時斷線後保留原角色、分數與已猜中狀態；時間由伺服器時鐘計算，不因斷線重置。服務重啟仍會清除記憶體房間，與目前其他遊戲一致。

## 實作順序與驗收

1. 抽出共用畫布核心，同時保證原本 `/studio` 的色輪、圖層、去背與儲存不退化。
2. 實作純伺服器遊戲引擎與題庫：階段／私密題目／答案別名／計分／期限／中途加入／踢人。
3. 接入大廳、房間、共用遊戲 UI、角色表情與對局歷史摘要。
4. 實作筆畫批次與 SSE、快照補齊、重連及輪詢回退；在手機畫布測試觸控與方向鍵。
5. 用 2 人與 3 人實玩測試整局，涵蓋畫者失線、猜題者重連、揭曉前看不到答案、畫布版本補齊、投稿比例與私人圖庫儲存。Windows／Linux 全套測試通過後，在 `shhuang.cc` 驗證公開網域即時筆畫不被 Tunnel 緩衝，並實際由兩個帳號跨裝置遊玩。

後續可再加提示、成就、主題背景與短音效；第一版先把「畫得順、看得到、猜得準、斷線能回來」完成。正式實作前建議確認：每人畫一回合是否足夠，以及畫作是否只由畫者手動存入私人圖庫。
