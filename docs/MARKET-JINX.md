## 玩家與管理者流程

首頁第六張卡片進入 `/market`，使用既有 BGA 登入與帳號選單。未登入返回登入頁，登入後回到遊戲。這是每日預測，不建立一般遊戲房間。正式程式初始沒有示範交易日、行情、投票或積分；由管理員手動開始。

管理員到「管理結算」，確認交易所行事曆並勾選交易日確認後建立日期。每個交易日只建立一次，投票截止為前一個**日曆日**台北 21:00。系統不自動計算假日或下一交易日。截止已過的日期不能建立，帳號每日期一票，截止前可修改。以取得 SQLite 寫入鎖後的伺服器時間裁決。

暫定六區間：`≤ -5%`、`> -5% 且 ≤ -2%`、`> -2% 且 < 0%`、`> 0% 且 < 2%`、`≥ 2% 且 < 5%`、`≥ 5%`。剛好 0（含 -0）是和局。猜中 +5、猜錯 -1、和局 0、未投票 0。等機率隨機選六項的非和局期望積分為 0；這不是各區間的歷史機率或真實期望值。沒有歷史機率假設或行情 API。

管理員暫定交易日台北 13:30 以後可輸入指數收盤漲跌幅，先預覽人數與本人積分影響，再確認結算。接受有限十進位數值，範圍暫定 ±100%，空白、百分號、非數值、無限值拒絕。相同結果不重結算。更正必填原因，先記負向撤銷舊分數，再以新結果重新計分；原結果與原因永久保留。管理員可查看所有日期的結果版本，玩家只取得自己的投票、積分異動與總計。

六張卡片下方是等尺寸純色圖片佔位，圖片待提供。免費娛樂，無現金、無兌現。桌機 1280×720 優先，手機兩欄卡片、可垂直捲動。

## 實作與協議

- `public/market-rules.js` 是瀏覽器／Node 共用規則；門檻、分數、時區、截止時間、結算時間、輸入界限與選項集中於 CONFIG。建立日期時存完整規則快照，舊交易日用其原快照裁決，不重新解讀歷史。
- `src/market/store.js` 重查 canonical users UUID、disabled 與 role。客戶端提供的 userId／role／clock／rules 不作為權威。所有寫入及積分更正以同步 `BEGIN IMMEDIATE` 一次提交，失敗全部回復。
- 寫入必帶 8–80 字元 requestId；同帳號同識別碼同內容回傳原收據，不重加分；同識別碼不同內容拒絕。投票 expectedRevision 從 0 起；結算 expectedRevision 從 0 起。投票版本衝突 409 時讀取最新票、保留待提交選擇並更新版本，玩家核對後明確重試；不自動覆寫另一頁的投票。截止後投票即凍結，已結算日期即使時間回退也不再接受投票。
- 瀏覽器投票不使用 localStorage 或假帳號。用伺服器時鐘錨點顯示時間，每 15 秒更新狀態，截止仍由伺服器裁決。網路結果不明時先更新查核，不自動重送寫入。
- 手動更新與寫入共用操作鎖，等待回應期間停用更新及表單；成功／失敗均解除本次鎖。結果不明時仍可按更新恢復。時鐘回退時投票 updated_at 不早於原 created_at／updated_at，截止判斷仍取寫入鎖後的實際伺服器時間。
- 頁面只列最近 100 個交易日與本人最近 100 筆積分異動；積分總額計算所有 ledger，沒有丟棄舊分數。管理員結果歷史附於這 100 日期之下。
- `config.marketClock` 只用於本地測試 harness 的注入；沒有 HTTP 或環境變數調時入口。正式 `createApp` 預設 Date.now。

| API | 方法 | 權限與目的 |
| --- | --- | --- |
| `/api/market` | GET | 登入者：本人狀態、日期、戰績 |
| `/api/market/vote` | POST | 登入者：本人提交／修改 |
| `/api/admin/market` | GET | 管理員：加上參與人數與結果歷史 |
| `/api/admin/market/rounds` | POST | 管理員：確認建立日期 |
| `/api/admin/market/preview` | POST | 管理員：預覽，不寫積分 |
| `/api/admin/market/settle` | POST | 管理員：確認結算／更正 |

寫入沿用既有同源檢查、JSON body 限制與 session；投票及管理操作各每帳號每分鐘 60 次。前端 busy 只是操作提示，去重與並行安全由資料庫負責。

## Schema 與完整備份

目前 schema **14** 新增五張市場表：`market_rounds`、`market_votes`、`market_settlements`、`market_ledger`、`market_requests`，保留 main schema 13 的 `draw_word_exclusions`。先前 PR #38 單獨使用的市場版 13 也可升級至 14，補上空禁題表；main 禁題版 13 補上空市場表。帳號、密碼雜湊、UUID、權限與已有功能資料保持原值，無新 BLOB 或外部檔案。舊 schema 1／3／5／7／10／11／12 的相關回歸保留。

現有完整加密備份包含全部表。備份驗證新增市場歷史語意檢查：日期與規則、投票截止、連續結果版本、命中計分、每次更正的撤銷及目前結果一致性。完整的禁題版／市場版 13 均可冷備份及還原；缺表、部分市場表或損壞積分拒絕。14 版必須同時具備兩方所有表。合成資料驗證匯出／verify／預演／還原保留投票、收據、更正 ledger、禁題稽核與原密碼登入，還原仍撤銷 sessions；來源不升級，只有還原副本升級。使用者既有備份 UI 不在這次操作範圍。

schema 14 資料不能交給只支援 13 或 12 的舊程式；兩種 13 的舊程式也不能互換資料。未提供降版 migration；如將來需回退，須一起恢復升級前的完整備份及舊程式，不能只換程式讀新版 DB。本次沒有執行正式升級或資料切換。
