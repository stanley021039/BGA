# 房間首次點播自動開啟播放器（#256／#261）

2026-10-25；基準 main `3ddf7c0d9b45182349597caaede52fa48dacf599`，候選 2.46.0。
使用者本輪要求處理媒體兩票，取代 #261 先開票暫不實作的階段限制。

## 本批範圍與行為

- #256 與 #261 一起實作，以較新的 #261 精確觸發條件為準：已連線的同房玩家，從 current 與 queue 都空，收到第一筆正在播放的媒體時，自動顯示既有 compact 播放視窗。
- 不套用大廳，不新增另一套播放器。已開視窗保持既有 full／compact／bar 及分頁；加歌、切下一首、暫停／續播不重複開窗。
- 伺服器原先在 stop 後保留 autoStart=false，即使全空後重新點歌也不開始播放；依本次「空→有人點播即播放」需求，只在加入前 current／queue 皆空時開始新播放。有待播清單的停止狀態保持停止，新增點播不替管理者續播。
- 初次載入、重新整理與斷線恢復只建立快照基準，不重播既有開窗事件。關窗後同一段非空播放不自動再開；真正回到空清單後的新點播可再觸發。
- 分頁隱藏、遊戲 modal、背景模式與共用遊戲全螢幕期間暫緩。只有一筆待開事件，不新增輪詢／timer；切歌、停止、換房、離線或卸載會使過期事件失效。恢復可操作時，仍為原曲且仍在播放才開啟。
- 非 modal 開窗後還原鍵盤焦點，包含原先焦點為 body 的情況，不搶走聊天輸入。沿用既有幾何限制、縮放／拖移與生命週期。
- 音樂使用現有 align 嘗試依全桌進度播放，不改個人音樂啟用／音量設定。影片僅在既有影音同意後載入；拒絕時保留可點的接受入口。瀏覽器阻擋播放時保留原生播放器與恢復入口，錯誤提示不定時消失。

## 設計與效能

沿用第三份 Figma 的既有共用媒體視窗及已實作 compact 介面；本批只接觸發行為與既有提示持續條件，未新增視覺設計或聲音資源，未修改 Figma，也不宣稱設計文件或正式站已同步。背景／全螢幕等待觀察僅限 body class；既有 subtree observer 只觀察 dialog open／aria-modal（含手機聊天室抽屜），避免追蹤所有動畫 class。
