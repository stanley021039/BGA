# 傳情畫意：倒數到時自動傳頁

2026-10-13。來源：使用者要求移除「全員送出，傳下一頁」，改為時間到傳下一頁。此筆取代初版房主手動傳頁與共用畫板文件中「自動截止待定」的描述。

## 規則

- 每頁維持 90 秒。即使全員提早送出，也等共同期限到達才傳下一頁。
- 移除房主傳頁按鈕；伺服器執行換頁，沒有房主必須在線或點擊的條件。
- 玩家可以提前送出或略過；送出後不能修改，仍看得到本頁剩餘時間。
- 逾時尚未送出：將伺服器已接受的私人草稿送出；沒有內容則標記略過。最後一頁到時自動揭曉完整傳遞簿。
- 重新整理不延長時間。舊 stepId、期限後的新提交、已送出後的草稿覆寫均拒絕；相同手動送出 requestId 保留去重。
- 仍按固定入座順序交替畫圖／猜詞；尚未揭曉前只看上一頁與自己的草稿。

## 實作

`TelephoneRoom.auto()` 由房間 scheduler 每 400ms 檢查 deadline，將缺少的提交補為已同步草稿或空白略過後，一次提交每本的當頁；新 stepId／deadline 或 finished 只產生一次。廢除的 advance 指令不允許提早傳頁。

`POST /api/telephone/draft` 沿用帳戶與房間席位驗證，以 stepId／requestId 驗證私人草稿，128KiB body 上限及每帳戶 120 次／分鐘上限。畫作仍限 100 筆／3,000 點、猜詞 80 字。每人最多一份當頁草稿、128 個有界草稿 receipt；不把反覆完整草稿寫入歷史，避免大量筆畫使對局容量快速耗盡。歷史照舊保存提交頁面的 delta，八席最大畫作回歸已驗。

瀏覽器以單一在途請求及最多一個排程同步最新草稿，通常每秒合併一次，接近截止時縮短等待。同步回應不替換同頁画布或輸入框；私人草稿可從伺服器回復。當前已送出也使用同一 CountdownBar。畫布／玩家／聊天室仍採共用三欄與手機換列。

## 驗證與界線

- 引擎、客戶端、HTTP、scheduler 共 37 項針對性測試通過：3–8 席映射、未到時／準時、全員完成不提早傳頁、私人草稿、空白略過、截止後拒絕、旧頁拒絕、同 receipt、最後一刻同步與逾時停筆、AI 與期限順序、最後揭曉、八席歷史容量、body 上限、未登入與錯誤 method。
- 測試站兩個真實三席房間，各跑完兩個 90 秒頁面：全員提前送出仍等時間；另一桌房主關閉頁面，作畫草稿與未送出的猜詞仍在到時保留，空白頁略過。正常揭曉三本、每本三頁；再次開局畫布空白。
- 五種畫圖／已送出／猜詞狀態，1440px／390px 共 10 次尺寸檢查：無傳頁按鈕、教學隱藏、無水平溢出；桌機三欄等高，手機聊天室 440px。持筆／放開／同步回應期間的 rAF 採樣無意外白屏，接手者到換頁才看到畫作。
- 證據：本輪 `telephone-timed-preview.cjs`／`telephone-timed-evidence.jsonl`、桌機手機截圖與 targeted Node 輸出。某次重整後的猜詞截圖被原有媒體同意視窗覆蓋，該次可確認背後尺寸與草稿回復，不宣稱已對該張遮罩下畫面做完整視覺驗收。

只能保留截止前已被伺服器接受的內容；斷線或背景頁尚未同步的最後筆跡／輸入不能保證納入。私人草稿不跨伺服器重啟續局，全人類長時間離線仍沿用既有房間清理規則。沒有修改共用 renderer／SSE、資料庫 schema 或正式發布來源；真人觸控、全部八席原生場次與完整 PR 驗收未在本輪聲稱通過。候選測試服務已重啟使用新引擎。

## 2026-10-25 Issue #263：分開設定階段時間

此段取代上方「每頁維持 90 秒」作為目前規則；90 秒仍是兩項設定的預設值。

- 房主或已授權設定管理者可在等待室分開設定「作畫時間」及「文字／猜題時間」，各可選 60、90 或 120 秒；文字時間同時用於開局出題階段。管理者權限沿用 main #265 的共用契約。
- 設定儲存在房間狀態，所有玩家及觀戰者讀到相同值；開局後不允許修改，重新開始沿用該房間設定。
- 伺服器依當前階段設定 deadline，前端倒數使用相同值；到期自動傳頁及草稿處理規則維持不變。
- 舊版本持久化房間缺少兩項新欄位時，作畫與文字均回退 90 秒；保留既有截止時間，後續階段仍產生有效倒數。
