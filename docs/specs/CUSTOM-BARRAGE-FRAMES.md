## 建議方案

第一版使用**一張靜態 PNG 框圖＋表單設定九宮格切線**。上傳頁提供96×96模板，四邊各24px，中央留空；作者只需畫四角與邊線，系統用 CSS `border-image` 保留角落、拉伸邊線，文字仍是可讀的DOM。設定只能填有界的數字與預設配色，不接受HTML、CSS或JavaScript。框圖與文字分離，短句／長句不必各做一張圖。

這是專案設計推論。九區切片及中央預設不繪製的行為來自 [W3C CSS Border Images](https://www.w3.org/TR/css-backgrounds-3/#border-images)；實際文字背景由本站提供，避免框圖遮住內容。

| 候選格式 | 使用者操作 | 伺服器／效能影響 | 決定 |
| --- | --- | --- | --- |
| 靜態PNG＋九宮格設定 | 一張圖；模板及滑桿可立即預覽 | 可解碼重存、限制像素；快取一次，不進每次state的base64 | 首選，先支援這種 |
| 靜態WebP | 與PNG相同，但作者工具支援度需驗 | 可降低檔案量；必須拒絕動畫並完整解碼 | 後續擴充，不阻擋首版 |
| SVG／任意CSS | 邊框可伸縮，但作者必須懂程式 | 外部資源、事件／腳本、複雜filter及樣式注入都需獨立處理 | 不作會員上傳格式；本站原創內建素材可用 |
| GIF／APNG／影片 | 可做動態框 | 與移動彈幕疊加，解碼／閃動／尺寸難約束 | 首版不支援 |
| ZIP或自訂封裝檔 | 需同時處理圖片與manifest | 增加解壓、路徑穿越／膨脹及版本相容性工作 | 單張圖已足夠，先不新增封裝 |

## 介面及格式

| 位置 | 功能 | 要保留的資訊 |
| --- | --- | --- |
| 收藏庫 | 新增「彈幕框」類別；我的／朋友分享／內建三種來源 | 名稱、作者、預覽、目前是否使用、分享狀態 |
| 上傳dialog | 名稱、PNG、四邊切線、框線厚度、预設底色；短／長文字即時預覽 | 總是能看見文字效果；錯誤就地提示，失敗保留草稿 |
| 彈幕輸入旁 | 調色盤或框框SVG按鈕，點開選框popover | 只收合不常用的選框；原文字輸入、發送、emoji仍常駐 |
| 接收者右上設定 | 「顯示彈幕框」個人開關 | 關閉只改本機，文字／emoji仍依原本彈幕設定 |

不把客製文字樣式做成任意內容；文字仍使用共用16px字級、穩定字體及本站背景色。作者框線不得覆蓋姓名或訊息。預覽至少包含1字、40字、16字暱稱、emoji及中英混排。框圖不帶音效、不新增移動方向或循環動畫。

建議匯出用的可攜metadata（未實作）：

```json
{
  "format": "afterhours-barrage-frame",
  "version": 1,
  "name": "像素薄荷框",
  "slice": {"top": 24, "right": 24, "bottom": 24, "left": 24},
  "borderWidth": 12,
  "background": "dark",
  "image": "frame.png"
}
```

上傳UI將PNG與表單送到同一API，不要求一般玩家撰寫JSON。`image`只是匯出示例的固定檔名，伺服器不依任意路徑或遠端URL讀圖。四個切線必須為整數、相鄰總和小於圖片尺寸；框線厚度8–16px。以上數字是待實播驗證的專案預算，不是外部標準。

## 整合方式

| 層次 | 建議實作 | 現有接點／必要補強 |
| --- | --- | --- |
| 持久資料 | 新 `barrage_frames` 保存UUID、owner、name、mime、規格、版本SHA、bytes、shared及created_at；使用者選框另存明確FK | 參考 `src/artworks/store.js`；獨立種類避免框圖混進頭像／畫作列表，刪除後選擇回內建 |
| 收藏API | 列表、上傳、分享／停止分享、刪除、使用框框；每人最多30張 | 登入、owner及速率限制沿用；不能讓客端自報owner／sharing資格 |
| 彈幕POST | 送出訊息時由server解析帳戶所選frame，不接受任意url或原始樣式 | `src/app.js` 的social/barrage分支；記錄小型frame ID／version及切線，凍結此次訊息使用的版本 |
| 圖片受眾 | 分享框可給會員讀；私人框套用到房間彈幕時，給當下房員短期、綁定原bytes的受眾grant | 參考 `src/profiles/media.js`。圖片GET不得加入房間或刷新presence；不因發送一則訊息將整個收藏改公開 |
| 客端renderer | `GameShell`在bubble內增加預設背景與九宮格裝飾；使用可信資產URL及有界數值 | `public/shared/game-shell.js`、`game-shell.css`；文字用textContent，圖片失敗立即回預設框 |
| 快取 | 頁內LRU最多16張、同ID/version只decode一次；資產URL帶版本SHA | 伺服器state不帶圖片bytes；背景／退出清理節點，正在播放的私人版本grant設短期限 |
| 備份還原 | 增加schema migration、驗證器與統計；完整DB備份含blob／metadata／選擇及擁有者 | `src/data/transfer.js` 的BLOB計數、版本介紹表、相容規則必須同步；不能只新增DB表就聲稱移轉已相容 |

## 上傳與播放邊界

首版建議最多256KiB／張、最大512×512、最多262144解碼像素；最多30張／人約7.5MiB原始圖片。必須解碼PNG、驗證完整資料與CRC／尺寸、拒絕APNG、重編碼去掉metadata；不能只相信副檔名、MIME或IHDR。建議使用成熟圖像解碼器並固定依賴版本，**目前無該解碼器，屬新增相依工作**。

現有 `imageOf` 主要驗base64、檔頭及尺寸，不能直接當新框圖的完整解碼驗證。上傳限量、檔案內容驗證、隨機ID及安全提供圖片的原則參考 [OWASP File Upload Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)；上述PNG-only與數值限制是本專案取捨。

框框只在訊息建立時算一次尺寸；沿用8秒translate動畫，不逐幀算layout或重新decode。原本最多四軌、滿軌不排隊；加入框後要依實際bubble高度及舞台高度限制同時可用軌數，不能照搬固定百分比讓大框重疊。不要為框圖增加每秒網路請求、濾鏡動畫或永久will-change。

## 驗收與實作順序

| 階段 | 可驗收結果 |
| --- | --- |
| A：內建樣式及選框 | 三種本站框與預設框；長文字不遮擋、個人開關、四軌／減動／退出原行為保留；無新DB／上傳承諾 |
| B：收藏上傳 | PNG模板、解碼重存、所有者／分享／私人受眾、版本快取、刪除／停止分享回退；建立新schema與完整移轉回歸 |
| C：分享品質 | 1280×720及手機實播；最多4則、混合短長句、弱網／壞圖／刪除；200%文字尺寸和不同stage高度；CPU／長任務及對比原彈幕 |

最重要的回歸：私人圖外人403、資產GET不延長房間壽命、舊版本grant只回當時bytes、框圖壞掉文字仍可讀、非法切線／解碼炸彈拒絕、改框後舊訊息不跳樣式、圖片只取得一次、備份還原保留原帳戶與框。預覽與上傳完成不等於已上線或多人效能合格。
