## 實作契約

`src/rooms/permissions.js` 依目前房間的有效人類座位與角色提供 `canManageSettings`、`canStartGame`。共用開始 API 及八款引擎的 configure 方法使用共用伺服器判定；猜歌的設定仍走原本 configure action。客戶端宣稱角色或 capability 不授權。

郎中建立房間時先在同一建立交易內加入房主，再由該座位套用初始設定，避免以尚未存在的房主執行 configure。建立設定不合法時仍走原有建房失敗收尾。

純 AI 引擎試玩仍允許真實 bot 房主在 configure 初始化規則，但不授予公開管理角色；HTTP 的操作身分仍取自登入帳戶的座位，不接受提交的 bot id。設定權限拒絕統一回 403／`HOST_ONLY`；送禮原本的 400 拒絕測試已更新為此明確權限契約。

前端 room store 分開提供 `settingsManager`、`gameManager`，保留 `host` 身分供房主專屬操作使用。明確 permissions 缺少能力時拒絕；沒有 permissions 的舊快照僅房主可回退。降級、離席及 terminal state 撤銷能力；設定元件採用伺服器目前值，取消尚未送出的草稿。已送出的請求仍由伺服器接收時的角色與遊戲階段裁決。

同時修改沿用現有序列化伺服器處理：最後成功接受的設定為權威值，經現有 snapshot／版本同步；不新增背景自動重試。已有未送草稿的編輯者保留自己的草稿；降級時丟棄草稿並改唯讀。

猜歌設定區改用 `UiCheckbox`／`UiField`，沿用既有選項卡。`UiCheckbox` 支援字串陣列與 label 的預設 slot；不增加外觀變體。外觀依第三份 Figma 的既有 Stitch 共用元件，不新增設計稿。

畫猜失敗重試的 footer 不再被父 Grid 固定為 48px；按實際兩列內容保留高度，避免重試按鈕溢出並被開始按鈕蓋住。設定內容維持原本局部捲動。
