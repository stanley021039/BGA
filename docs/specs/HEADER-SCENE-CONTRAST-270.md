# 大廳透明頁首與背景對比（#270，含 #268）

2026-10-25；PR #281 候選 3.5.0，基於 main `a016ced`（3.4.0）。本文件取代本批先前「已有透明 CSS，因此 #270 已完成」的結論。透明與文字可讀性是兩個驗收條件；原先只驗原本／法庭共八組不足以涵蓋 #268 合併進來的要求。

## 行為與共用責任

頁首保持透明、無獨立底條，品牌、導覽與頂層 ghost 操作依實際大廳背景選擇明暗前景。預設背景沿用網站主題；法庭日間用深字、夜間因既有背景濾鏡改白字，其餘深色場景用白字。舞廳、教室與夜間法庭含跨越亮暗區的細節，使用 1.5px 黑色文字描邊及不模糊的圖示輪廓；不更改原始背景素材。

顏色與輪廓角色由 `stitch-tokens.scss` 定義，`scene-view.scss` 依現有背景屬性配置，`controls.scss` 的共用 ghost 元件消費語意變數。只配置頁首頂層觸發鈕；浮動選單、帳號選單、對話框及其他頁面沿用自身主題表面。選取的實底圖示不加輪廓。hover 與鍵盤 focus 使用相同場景角色，focus 另保留成對輪廓。

不新增執行期取樣、事件訂閱、計時器、素材或網路請求。新增背景或修改素材／濾鏡時，須重新檢查完整背景目錄。

## 可重跑驗證

先建置前端，於具有 Playwright、pngjs 與 Edge 的環境執行 `node tools/qa/header-contrast-270.cjs`。需要時透過 NODE_PATH 提供瀏覽器測試工具，不增加產品執行期依賴。

腳本建立 ignored work 下的隔離 SQLite 與合成帳號，使用既有獎勵解鎖工具；不操作正式資料。依 `public/shared/lobby-backgrounds.json` 遍歷全部十款背景 × 深淺主題 × 1920／390px，共四十組，實際從 API 切換背景並等待大廳更新，不靠重新整理才能生效。

每組保留完整頁面及頁首 PNG、idle／hover 對比、Tab 焦點、選單開啟／Escape 關閉結果；最後再驗重載。隱藏頁首但保留幾何後取樣背後實際像素，區分原始背景／控制表面的對比與已繪製輪廓的對比；文字要求 4.5:1，圖示 3:1。原始對比不足時，必須確認實際 computed stroke、paint-order 或不透明圖示輪廓及其前景配對，不能把透明本身算成通過。故意注入舊主題配色，確認測試確實能偵測深背景上的深色文字。

部分舞廳與夜間法庭的原始藝術背景對比仍不足；這些組合依賴實際輪廓，白字／黑邊配對 21:1，不能宣稱全部原始背景樣本均達 4.5:1。此為瀏覽器樣本與視覺檢查，非第三方無障礙認證。

Edge 使用 reduced-motion 穩定取樣；沒有涵蓋每個動畫影格、Safari、實體手機觸控或正式站。最終結果與證據路徑見[本批進度](../ISSUES-262-263-270-PROGRESS.md)。使用者已接受此輪透明頁首／配色／細描邊外觀並要求後續審查與 CI；Ready 轉換仍須依使用者規則另取得確認。
