# #59 免 token 跑團初版：霧港鐘聲

2026-10-09。使用者確認先做免 token 可玩初版。原創簡化合作規則，不宣稱實作 D&D／CoC，也不稱規則腳本為即時 AI KP。狀態與實際驗證見 [本輪進度](../TRPG-FIRST-EDITION-PROGRESS.md)。

## 最小可玩範圍

- 大廳新入口，沿用帳號、房間、邀請、權限、重連及歷史；1–6 人，單人也可試玩，腳本測試夥伴可補席。
- 六幕原創短篇「霧港鐘聲」，三個地區的文字場景與路線圖；三種角色各有一項 +2 專長。
- 每幕依入座順序輪替領隊。領隊選觀察／交涉／冒險；其他隊友選協助／整備，所有人都可寫 160 字以內的一句行動。
- 觀察難度 6、補給 1、成功線索 1；交涉難度 7、補給 0、線索 1；冒險難度 8、補給 0、線索 2。初始補給 4、每人專注 3。
- 合適專長 +2，最多兩位協助者各花 1 專注提供 +1；按入座順序取前兩位，其他協助者不扣專注。整備 +1 專注（上限 3）；領隊整備時放棄本幕專長，避免免費整備成為永遠最佳選擇。
- 伺服器 d6 + 專長 + 協助：達難度成功；差 1–2 為線索 +1、危機 +1；更低為危機 +1（觀察／交涉）或 +2（冒險）、失去最多 1 補給。失敗仍換幕，沒有人淘汰。
- 六幕後線索至少 5 且危機最多 7，鐘聲回港；否則帶著約定回港。結局文字承認代價，不偽造勝利、不羞辱落敗者。

## 從角色記憶採用的精進方法

本輪同一實作者從玩家／設計／程式視角自查，沒有另外找 agent 投票或真人訪談。

| 玩家 rubric | 本輪設計／反例／修訂 |
| --- | --- |
| P1 核心互動 | 每位玩家都有本幕行動，最多六席六幕至少各領隊一次。不能只讓房主決定全部；領隊按規則輪替。 |
| P2 決策公平 | 選擇前公開難度、補給、成功收益與失敗代價；骰子和結果由伺服器判定。角色扮演文字不由隱藏裁判改判，提交前不公開其他席位描述。 |
| P3 資訊清晰 | 名單、本人、領隊、階段、專注、隊伍資源、合法操作常駐。介紹清楚標示「規則主持／不連 AI」。 |
| P4 節奏 | 不設倒數催促慢輸入；顯示尚未準備者。離線隊友滿 15 秒且尚未提交時，房主可明確確認本幕休息；不代替其擲骰／花專注。離線領隊可踢出交棒，場景識別碼更新，全桌重新準備。 |
| P5 包容 | 角色可重複，沒有長篇即興或原規則知識門檻；行動描述選填，失敗不淘汰，沒有 XP、每日任務、個人排行榜或懲罰徽章。 |
| P6 因果回饋 | 公開骰值、角色加成、協助加成、難度和實際資源变化。旅途手記跨幕保留，進行中結果不會被自動倒數奪走。 |
| P7 可靠性 | 每個場景有不可重用 UUID；指令有 requestId／收據去重；舊場景／重開／交棒指令拒絕；取消舊請求、單一輪詢，寫入失敗不自動重送。 |
| P8 重玩 | 骰子、角色組合和資源分配形成差異，但初版只有一篇六幕故事，不能宣稱多劇本／長期重玩已驗證。完局可重新選角重開，歷史保留上一場。 |

依 [玩家研究 rubric](../research/PLAYER-REVIEW-RUBRIC.md)、[玩家角色記憶](../agents/PLAYER.md)、[設計攻防方法](../agents/MEMORY-PROTOCOL.md) 設計。上述是機制與設計推論；主觀樂趣、陌生人桌、大桌等待、真觸控及完整讀屏未測時標待驗，不給真人評分。

## 安全、恢復與後續界線

同帳號既有席位恢復、伺服器權限、歷史寫入失敗停止及房間閒置清理沿用既有程式。遊戲中不接受新席位／重新入座；房主只能替未準備的離線非領隊安排中性休息。去重只在該房間本次執行期，收據有上限，不提供跨程序重送保證。伺服器重啟會結束記憶體房間，歷史回看不是進度還原。

敘事／規則／檢定在 `src/games/trpg.js` 的獨立邊界；view 標記 `narratorMode: rules`。AI KP、自由文字裁決、AI 生圖、token 設定、場景編輯、可恢復長期戰役、成就與正式部署不在初版。若後續加入模型，另定費用／隱私／內容界線及失敗回退；不能讓模型直接覆寫權威骰子、資源、席位或獎勵。
