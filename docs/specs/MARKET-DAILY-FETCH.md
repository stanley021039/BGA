# 官方收盤每日有界抓取

2026-10-08，Issue [#66](https://github.com/stanley021039/BGA/issues/66)。本文件取代 `MARKET-AUTOMATION.md` 的「成功後每小時重抓／每次完整回補」政策；其他來源、日曆、截止及結算契約不變。候選實作，未部署。

## 已確認需求

- 台北交易日 14:00 開始，未取得有效同日資料每 5 分鐘重試至 16:00；当日成功永久停止自動重抓
- 首次補最近一個日曆月，以後只補缺漏，保留有界的較早待結算補抓
- 記錄嘗試次數及首次觀察到完整有效資料的時間；不能冒稱官方發布時間
- 逾時仍待處理，提供管理員手動重試；官方修正須人工審查，不自動改分
- 前端 15 秒內部 API 讀取、預測截止、下一交易日規劃與未知日曆處理維持原契約

## 時間與恢復

14:00、14:05、…、16:00 是最多 25 個時點，使用 Asia/Taipei 固定 UTC+08:00。每次 tick 只認領當前可用時點，不回放已錯過的時點，且兩次實際自動開始至少相隔 5 分鐘。例如 14:04 晚啟動後，最早 14:09 再試；排程時點用於去重與上限，不允許 14:05 一分鐘後再打。16:00 之後不啟動新的當日自動查核；已在截止前開始的請求可在截止後完成驗證。啟動晚於當日窗口時，當日缺漏進入管理員處理，不能藉歷史補抓繞過截止。

每個時點在網路前提交持久認領；程序中斷不重送已消耗的時點。系統時鐘回退也不重送較早時點。成功日以持久官方資料及成功狀態停止網路；若資料已寫入、既有回合尚未達可結算時間，使用已保存且通過驗證的證據結算，不重抓。帳務仍使用既有 transaction、round/result revision 與 ledger 唯一鍵。

日曆抓取／下一輪規劃獨立於收盤時點、歷史重試及截止狀態。官方明確休市不抓當日；未知日曆保留既有「不能推測下一交易日」語意，但不將整個自動化關閉。衝突年份的資料仍受原本寫入驗證阻擋。

## 歷史補抓

初次初始化按上一日曆月同日到昨日的區間列出已確認交易日缺漏；之後仍查 DB 缺漏集合，不下載已完整區間。當日與可見历史缺漏可合成一批，另外最多輪流處理一個較早未結算月份，避免單筆飢餓及無界工作。

從未進入每日時點排程的歷史缺漏，最多 5 次自動嘗試，每次間隔至少 5 分鐘；次數持久保存，超過後須手動重試。曾進入每日排程且已過截止的日期維持管理員處理，不在翌日藉歷史流程重新打開。已寫入日期只讀 DB。官方 API 只能給整月時，各來源月報在該批只下載一次，選定日期之外的資料不寫入；這不宣稱可避免來源回應中夾帶已成功日期。

## 持久資料與觀察

沿用 `market_automation_state` 的 `status` 行，新增 `fetch:YYYY-MM-DD` 行保存 status、排程時點、automaticAttempts、manualAttempts、最近嘗試時間／種類／錯誤及 firstValidObservedAt。沒有新增 table、column 或 schema 版本；完整備份自動包含這些行，語意 validator 驗證日期、時點、數量、狀態及關聯官方證據。

`firstValidObservedAt` 在 `recordClose` 的同一筆 transaction 首次存入有效證據時寫入，後續手動核對不覆蓋。歷史既有資料沒有記錄時保持空白；不得從官方網頁的詮釋資料更新時間推估。既有舊資料只有在本版重新驗證使用時才開始觀察，不能把此時間說成當年實際可用時間。失敗、無回應或未完成 transaction 不能建立成功。

程式可讀舊 status-only 記錄。雖然 SQLite 結構不變，舊版完整備份 validator 不認得新增 fetch keys；回退／匯出須使用懂得此語意的程式或升級前備份，不能宣稱所有舊版工具都相容。本工作不操作正式資料。

## 手動處理

管理員在獨立日期表單明確確認後，POST `/api/admin/market/recheck`。伺服器先驗證身份、確認、有效日期及可查核時間，才允許官方網路。未來日期、當日 14:00 前、停用外部副作用時拒絕；自動工作先完成後再序列化手動工作，並拒絕第二筆同時手動作業。前端不自動重送 POST。

成功的官方修正仍由 `recordClose` 原本已結算 fingerprint 差異路徑標記 review，保留原值、原證據及積分；管理員原有預覽／確認更正流程另行執行。手動失败不清除成功紀錄或原本截止標記，不重新打開自動排程。

## 官方來源與非保證

[MI_INDEX](https://data.gov.tw/dataset/11555)、[MI_5MINS_HIST](https://data.gov.tw/dataset/11755)、[FMTQIK](https://data.gov.tw/dataset/11672) 標示每日更新，沒有 14:00／16:00 發布 SLA。這是產品重試政策，不能把到達某個時間當作收盤有效性證明。精確日期、完整欄位、官方兩來源以上及既有百分比交叉核對持續必要。

## 驗收

deterministic clock 覆蓋台北日期／假日、14:00／16:00 首尾、晚 tick 不補跑、25 次上限、失敗／不一致、重啟及成功停止、窗口外啟動、歷史五次預算、較早月份公平性、並行及 abort cleanup。API／UI 覆蓋管理員身份、輸入、確認、停用、重复送出与時間觀察。既有原子結算、官方事後修正、帳號及加密備份測試仍需通過。最終命令、固定 base/head、spec 與品質兩回合結論以 PR 驗收紀錄為準。
