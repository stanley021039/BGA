# #215 郎中房間面板與背景角色

2026-10-23；候選 2.41.0，基於 `674811c`。Issue：[UI 收合行為](https://github.com/stanley021039/BGA/issues/215)。本輪為隔離測試環境候選，尚未發布正式站。

## 已確認範圍

- 首輪三項皆限郎中；共用 `RoomSidePanel`、`RoomBackground` 保留後續遊戲接入能力。
- 玩家列表向左、聊天室向右收合，只留相反方向箭頭。桌機與手機首次進房均收合；開局、換階段及結算不重設手動狀態。
- 收合不改中央遊戲區尺寸、位置；沿用各階段既有布局。整塊玩家列表收合，不保留摘要；查看他人大釜使用中央既有入口，移除列表重複按鈕。
- 聊天收合時保留草稿，新訊息只加未讀數，不自動展開；展開清除未讀。
- 背景只顯示同房成員，同步點擊或方向鍵走動。角色可以被面板遮住，不強制移位；遊戲／聊天操作不穿透背景。
- 手機採覆蓋抽屜，點外側只關閉，不走動；抽屜開啟時遊戲與背景 inert，Tab 留在抽屜，Esc 關閉。

## 實作

`src/rooms/space.js` 以 WeakMap 按實際 room 物件隔離暫存位置，移動不修改玩法版本或歷史。`POST /api/room-space` 沿用登入與座位驗證，由伺服器決定移動者，限制座標與頻率；僅郎中啟用。快照只輸出角色公開投影，不輸出藥袋等私有遊戲資料。

前端重用大廳角色 renderer，移動請求合併、限制頻率並在離房中止；面板內容以 v-show 保留草稿。手機抽屜 Teleport 到 body，避免被遊戲容器和頁首的堆疊範圍遮住；樣式限新元件，其他遊戲維持原有面板。專注全螢幕隱藏背景與側欄，退出保留原開關。

## 2026-10-23 第二輪：使用者五項修訂

本段取代前版箭頭位置、即時顯隱與聊天室內的角色入口；首輪遊戲範圍和中央區不因收合縮放的契約保持。

1. 郎中聊天室只保留 emoji 選單；角色表情由點自己的背景角色開啟，沿用既有社交 API／權限、角色素材與音效。伺服器將五秒內的既有表情事件投影到同房角色，不另造第二套傳送／音效事件。
2. 地板點擊顯示主色光點／擴散環，約1.1秒清除；角色、面板、聊天和手機遮罩操作不產生走動光點。
3. 左右面板及箭頭滑動280ms，保留草稿及中央區位置尺寸，減少動態時改為立即切換。
4. 兩側箭頭固定在面板垂直中央；手機以抽屜外框中央為準。
5. 收合僅在垂直中央留64×128px空白立體框邊，避免整條空白框遮住手機內容，只顯示箭頭及必要未讀徽章；玩家／聊天資訊隱藏且 inert。開啟時內容保留把手欄，避免操作覆蓋。

採用現有 UiPanel raised、UiButton 與 ReactionPicker 元件。原 Stitch/Figma 對照板尚未反映本輪修訂，不將舊圖視為新互動已同步；以本輪直接確認的規格與實際候選畫面為準。
