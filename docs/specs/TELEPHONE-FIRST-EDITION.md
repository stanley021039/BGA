## 規則與範圍

3–8 人，每人一個起始情境，依入座順序輪流接手傳遞簿。所有人同時作畫或猜詞，伺服器固定映射，接手者只收到上一頁。奇數人 n−1 頁、偶數人 n 頁，畫圖／猜詞交替，最後必為猜詞；這是本站的數位短局變體，三人也能試玩，不宣稱完全重現實體版。

每頁送出不可再改，requestId 可重試同一內容；全員送出後由房主傳頁。沒有倒數、勝負排名或淘汰；可以明確略過。本場角色順序固定，進行中不接受入座；有人離席或被踢，整場標中止並揭曉已送出的頁面，不重新洗牌造成傳遞错位。斷線可恢復既有席位，草稿在同分頁 sessionStorage，沒有跨裝置草稿同步；全人類離線滿既有 90 秒清理規則時，房間中止。伺服器重啟不續局。

題庫與你畫我猜分開：`telephone-prompts.js` 的原創生活／奇想各 20 句，專用 ID；預設兩類，房主可選單類，不接既有 custom 詞、禁題票或成就。理由：這款重點是情境變形，不是唯一正確詞的快速猜中；沿用舊短名詞和別款禁題状态會混淆玩法與管理。管理員編輯／投稿／禁題、更多題庫及評分留後續。

## 玩家方法與反例

沿用 [PLAYER rubric](../research/PLAYER-REVIEW-RUBRIC.md) 和 [記憶攻防](../agents/MEMORY-PROTOCOL.md)，由同一實作者自查，沒有其他 agent 投票或真人訪談。

| 面向 | 實作／反例處理 |
| --- | --- |
| 核心參與／公平 | 每人每頁都操作，各本同時傳遞，不能偷看整條鏈；不依畫技與速度計個人排名。 |
| 可理解性 | 階段、已送出名單、上一頁、本人操作常駐；確定送出按鈕附近顯示不可修改，避免每頁重複打斷的 native confirm。 |
| 節奏／包容 | 不強制倒數或寫出標準答案，可略過；全部準備好才由房主換頁。離席會影響全桌，離開前說明與確認。 |
| 因果／回顧 | 正常揭曉可選每本，完整畫作與猜詞按頁列出；中止與正常完局不同標記，歷史可重建傳遞鏈。 |
| 可靠／效能 | step UUID、指令去重與衝突檢查、權限；草稿跨 poll 穩定、同分頁 reload 恢復、取消舊 lifetime。每頁 100 筆／3,000 點、每筆 ≤256 點；歷史逐頁 delta，避免每筆操作複製整場所有圖。 |
| 重玩／未證實 | 40 題與玩家誤讀形成差異；朋友桌的笑點、題目品質、大桌等待與重玩性待真人驗證，不能以腳本猜詞當語義理解。 |

繪畫沿用共用 StrokeCanvas，不修改原畫猜 renderer／SSE。新玩法是私人本地草稿，完成整頁才提交；接手者要等傳頁才見完整圖，不是即時觀看其他人的活動筆。原子 canonical 呈現、復原與新頁清理需實際觀察；不能只用最終圖代替途中驗收。
