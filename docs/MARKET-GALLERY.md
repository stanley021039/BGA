# 股市冥燈：截止及審核制圖片庫

Issue [#44](https://github.com/stanley021039/BGA/issues/44)／Draft PR [#45](https://github.com/stanley021039/BGA/pull/45)，候選 v1.5.0、SQLite schema 16。本文件描述本 PR 的實作與隔離驗證，不代表已合併、部署或更新正式資料。

## 截止及既有紀錄

新交易日保存規則快照 v2：Asia/Taipei 前一個日曆日 23:59 整分鐘可預測，目標交易日 00:00 為排他截止。伺服器取得 SQLite 寫入鎖後才讀時鐘。既有 v1 的 21:00 截止、結算、票與積分不改寫，歷史快照仍可驗證及還原。六個區間、猜中 +5、猜錯 −1、0% 和局不計分維持原規則。

## 玩家投稿與抽圖

- 登入會員選一張 PNG、JPEG 或 WebP，至少勾一個既有區間及一天星期；全部七天表示不限星期
- 星期依目標交易日判定。區間與星期須同時符合；各組內符合任一項即可
- 作者 UUID 及上傳當下的暱稱來自伺服器帳號，新圖一律待核准；不接受客戶端作者、核准者或狀態
- 送出後不原地修改圖片或規則。新內容另送待核准項目，並計入投稿配額
- 進入每日預測、切換交易日或按「換一組圖片」時，每區間獨立均勻抽一張符合的已核准圖片；空池保留同尺寸佔位
- 抽圖狀態與投票分離。選擇區間、15 秒狀態更新、投票／積分重繪不重新抽圖；交易日與操作序號防止舊回應覆蓋新圖
- 投稿或核准結果不明時，重試沿用相同 requestId 與固定內容，避免重複投稿或重新擴大核准批次

## 管理員審核

管理頁提供待核准預覽、作者暱稱、区間／星期規則、篩選與勾選。可以核准已勾選或全部目前篩選結果；確認畫面明列張數並凍結 ID／版本集合。確認後的新投稿不加入這批。寫入鎖內重新驗證管理權限及每筆待核准版本；任一項過期則整批拒絕，要求更新後重新確認。核准將版本 1 待核准變為版本 2 已核准，保留核准帳號與時間。

## 安全及固定上限

伺服器先驗證登入、同源及操作頻率，才讀較大的投稿內容。PNG／JPEG／WebP 的宣告 MIME 必須與實際解碼格式相符；SVG、動畫、假檔頭、損壞圖與超限內容拒絕。sharp 完整解碼為 RGBA 後重新編碼 PNG，只保留 IHDR／IDAT／IEND 像素區塊，移除 EXIF、ICC、文字等附加內容。備份驗證另以有界 zlib、CRC 與 pngjs 完整解碼檢查 canonical PNG。

| 限制 | 上限 |
| --- | --- |
| 輸入檔案 | 2 MiB |
| 正規化 PNG | 4 MiB |
| 單邊／總像素 | 4096／800 萬 |
| 每帳號／全站張數 | 100／1000 |
| 全站圖片 bytes | 256 MiB |
| 單次核准 | 1000 張 |
| 同程序同時解碼 | 2；超出立即拒絕，不排無界佇列 |
| 每分鐘投稿 | 每帳號 6 次、每來源 IP 20 次 |
| 每分鐘核准／抽圖 | 每管理員 30 次／每帳號 60 次 |
| 每分鐘我的清單／審核清單／媒體 | 每帳號 60／60／360 次 |

待核准媒體仅作者本人及管理員可讀，一般玩家得到 404；已核准媒體仅登入玩家可讀。每次讀取重新查帳號及圖的狀態，使用 no-store、nosniff、same-origin CORP。圖片 ID 為伺服器 UUID，沒有由玩家指定的檔案路徑或編輯 API。

## 資料與完整備份

`market_images` 保存圖片 BLOB、作者、暱稱快照、區間／星期、像素、狀態、版本及審核紀錄。上傳圖片属于執行期 SQLite 資料，不提交 Git。

schema 16 精確檢查表的欄位／型別／PK／FK／unique／完整 CHECK 定義，空表也驗證。缺表、畸形表、壞圖片／規則／審核狀態／配額／收據均拒絕。舊 schema 1–15 可在還原副本升級；既有 BLOB 與 users 必須完全保留，只容許新引入的空圖片表。冷備份來源不改寫。

完整加密 export／verify／dry-run／restore 沿用既有工具。圖片 bytes digest 及新增圖片 metadata digest 都在副本還原前後比對。原帳戶、密碼 hash、市場歷史保留；還原仍依原政策撤銷 sessions、invites、resets。升版與 schema 升級沒有降版功能：正式導入前需完整備份及停寫計畫，舊程式不能開 schema 16。
