# 成就、動效與美術：實際角色攻防

日期：2026-10-05。這份記錄來自同輪agent訊息，不是虛構玩家訪談或一致投票。設計／美術／動畫方 `typography_design`；玩家方 `player_research`（成就spec最終執筆）；程式／資料方 `layout_design`；主agent實玩及整合。**文件與原型，不改正式遊戲source／規則、不部署。** 最終條件／優先級以 [成就與勝利紀錄](../specs/ACHIEVEMENTS-AND-RECORDS.md)為準，未回覆事項不寫成同意。

## 討論的共同前提

設計方提出幽默的正常遊玩時刻；玩家方要求找羞辱、誘導壞策略、施壓、灌水與隱私反例；程式方核對server predicate、持久identity、正常結算、冪等。解鎖可永久私人收藏，不加XP／排行榜／能力／每日任務，勝利及共享勝利紀錄分開。僅「私人通知」仍不能消除已知目標對策略的誘導。

本輪讀 `src/achievements/store.js`，只有四款入門＋第一桌，沒有draw hook／持久勝場。所有新增候選均為未實作。下表P1＝建議後續spec候選，不代表已獲實作／部署；P2＝待觀察／可靠metric；否決＝不進本批；文案＝不多頒一枚。

**最終優先順序已同步玩家spec**：首批P1為畫猜2、送禮2、同頻2、跨兩種遊戲探索1，共7項趣味／探索候選，另補中性draw-first-round；「原始4骰全1」「全員有效操作」由早期P1意向改列**P2研究**。歷史回應的「接受」是語意／条件接受，不代表仍以舊優先順序實作。

## 程式／資料事實改變了設計

設計方唯讀核對並傳給玩家與程式方：

1. `src/games/thunder.js:begin`維修僅己方車；需要before/after實際損傷變化。擲骰／确认不能當駕駛回合成就，round accepted全1還需本人完整合法turn＋正常完賽。
2. `src/games/poker.js:settle`以playerId Map累加各sidepot，輸出results只name/amount/hand。相同牌型、兩個贏錢者或兩個同名者都不是共享同pot；新紀錄需 immutable player/userId、gameRunId、per-pot winnerIds、退款分類。
3. 現 `src/achievements/store.js`持久表只入門永久徽章，`WeakSet`僅runtime結果去重。新勝利紀錄多次累積要transaction及durable unique settlementId，不能把WeakSet或房碼當跨restart idempotency。
4. 畫猜新候選没有現成award hook，有效畫筆／guess資料需server accepted，題詞只能在normal reveal後公開。客户端工具click可以造假，不能自行頒徽章。
5. `src/games/gift.js:rankPoints/buildDelivery`單件great/good/ok/noWay為3/2/1/-4，未排名-1；第一輪0分說法是未核對的錯誤草案。玩家最終spec指出後，設計方核source補正，不把錯條件當已存在規則。

玩家收到後在v2與最终spec採入限制；程式方角色文件由本人執筆，我不把未確認的schema當已存在功能。

## 動效与美術攻防：實際協作

程式方原先提「共看同步」「安全資料快照」兩圖案；設計方建議換成P1「相同心意三禮盒」與P2「三窗共看同步」，安全快照暫不做第三件。程式方回覆接受，並承擔Node generator、兩SVG、standaloneHTML及manifest，無app整合。

| 議題 | 設計方主張 | 程式／玩家回應與結果 |
| --- | --- | --- |
| 是否需要原創 | 既有Present／play可用，但缺同stroke與組合語意的相同心意／三窗同步，手刻SVG，不用bitmap。 | 程式接受24 viewBox、stroke1.8/currentColor，纯Node內建生成。沒有第三方圖像混入。 |
| 原型强度 | 700ms手動一次，小幅聚合／脈衝，不自動循環，reduced静態，文字16/14、44重播。 | 程式已產出source，同意hidden/pagehide清理，不接網路、YouTube或DB。 |
| 「撞車」名字 | 禮盒碰巧相同，不用真正車禍／爆閃／震動；图三盒不是成就3份門檻。 | 玩家成就门槛改2份，prototype視覺仍是概念；最後名稱若變可改文案，不改規則。 |
| 共看圖示放哪 | status圖示不在iframe上，不遮任何真player控制，不假裝圖示代表已測同步。 | 程式指出YouTube iframe尺寸／可見性政策，寫入共看spec；原型無player，清楚標模擬。 |
| 動效vs資料 | 畫猜開說明錯過揭曉先結果快照／回看，不加長動畫。 | 主agent實玩回報；玩家強烈同意P0快照先於成就演出，設計計畫A00收錄。 |

孤立原型：[展示](../prototypes/motion-art.html)、[禮物SVG](../prototypes/gift-coincidence.svg)、[共看SVG](../prototypes/watch-sync.svg)、[manifest](../prototypes/motion-art-manifest.json)、[生成器](../../tools/prototypes/generate-motion-art.cjs)。程式方已回報生成／語法／`--check`通過；設計方唯讀source核對700ms、reduced、hidden cleanup及無網路依賴，不把這當正式遊戲UI試玩。

主agent後續在原Chrome背景測原型：兩個按鈕各一次，均觀察「播放中→完成」、無自動循環，CSS配置700ms、控制44px；390×844頁面內容寬375無水平溢出，之後還原1767×1196，proof `work/agent-prototype-proof.png`。設計方閱本地proof確認內容／字圖，沒有操作Chrome。reduced只有source確認、未瀏覽器模擬；沒有200%互動實測，亦不據此宣稱正式遊戲通過。程式方另把footer更正為本人收禮至少兩份同gift，圖案三盒非判定門檻。

## 未收斂與下一輪

P2 erase／repair／fold／split-pot／公路最大值保留待驗證，不先做圖標演出吸引玩家追目標。全桌有效參與與跨遊戲正常單位由server spec明確定義；收藏通知可關／不展示仍未實作。詞語可由真人小桌測，但不能據agent喜好宣稱玩家都喜歡。

玩家最終執筆勝利／趣味成就spec，設計方本記錄保存前後反例；主agent整合 [roadmap](../specs/AGENT-UPGRADE-ROADMAP.md)。來源與角色記憶遵守 [記憶協議](../agents/MEMORY-PROTOCOL.md)，研究資料不等於授權。
